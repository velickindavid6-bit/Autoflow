# Выкладка AutoFlow

Здесь две части. **Для рассылки по компаниям нужна только первая**: демо на GitHub Pages. Вторая (настоящий сервер) пригодится, когда появятся живые пользователи.

---

## Часть 1. Демо на GitHub Pages

**Почему демо, а не сервер.** GitHub Pages отдаёт только готовые файлы и не запускает Node.js, поэтому на нём работает демо-версия: «сервер» в ней работает прямо в браузере посетителя. Данные остаются в его браузере, письма и сообщения Telegram показываются в окне «Демо-почта». Настоящий сервер лежит в том же репозитории, и на него можно сослаться в письме.

**Что понадобится:** аккаунт на [github.com](https://github.com), установленный [Git](https://git-scm.com/downloads) и Node.js 22.5+ (он нужен только чтобы пересобирать демо после правок).

### Шаг 1. Подготовка (5 минут)

1. В файле `LICENSE` замените `<ВАШЕ ИМЯ>` на своё имя.
2. В `README.md` замените `ЛОГИН` на ваш логин на GitHub (в ссылке на демо).
3. Убедитесь, что в проекте нет секретов: файла `.env` быть не должно в репозитории (он в `.gitignore`, это нормально, что он лежит у вас на компьютере). Токен Telegram-бота и пароли никогда не должны попадать на GitHub.
4. Страницы «Условия» и «Политика» в демо помечены как «Демонстрационный проект». Для рассылки этого достаточно.

### Шаг 2. Создайте репозиторий

На github.com: **New repository** → имя `autoflow` → **Public** → **не** ставьте галочки «Add README / .gitignore / license» (они уже есть в проекте) → **Create repository**.

### Шаг 3. Загрузите проект

В папке проекта выполните (подставьте свой логин):

```bash
git init
git add .
git commit -m "AutoFlow: первая версия"
git branch -M main
git remote add origin https://github.com/ЛОГИН/autoflow.git
git push -u origin main
```

Если Git просит войти: GitHub не принимает обычный пароль от аккаунта. Проще всего поставить [GitHub Desktop](https://desktop.github.com) или выполнить `gh auth login` (программа GitHub CLI), либо создать «Personal access token» в настройках аккаунта и вставить его вместо пароля.

После загрузки проверьте, что секретов нет: `git ls-files | grep -E "\.env$|\.db$"` должен ничего не вывести.

### Шаг 4. Включите GitHub Pages

Репозиторий → **Settings** → **Pages** → **Build and deployment** → Source: **Deploy from a branch** → Branch: **main**, папка **/docs** → **Save**.

Через 1–3 минуты вверху страницы появится адрес: `https://ЛОГИН.github.io/autoflow/`. Откройте его.

### Шаг 5. Добавьте ссылку на код в демо

Откройте `demo.config.json` и впишите адрес репозитория:

```json
{
  "repoUrl": "https://github.com/ЛОГИН/autoflow",
  "outDir": "docs",
  "paymentsMode": "demo"
}
```

Затем пересоберите демо и загрузите изменения:

```bash
npm run build:demo
git add .
git commit -m "Ссылка на исходный код в демо"
git push
```

В правом нижнем углу демо появится «Исходный код →».

### Шаг 6. Проверьте как посетитель

Откройте ссылку в приватном окне и **с телефона**. Пройдите: регистрация → нажмите «Демо-почта» → «Подтвердить email» → выберите тариф «Про» → создайте задачу. Если всё работает, ссылку можно отправлять.

### Обновление демо после правок

```bash
npm test               # убедиться, что всё работает
npm run build:demo     # пересобрать папку docs
git add . && git commit -m "Что изменил" && git push
```

Если забыть пересобрать `docs`, во вкладке **Actions** на GitHub появится красный крестик: проверка CI напомнит, что демо отстало от кода.

### Оформление репозитория (это тоже часть портфолио)

- В правой колонке репозитория (шестерёнка у «About») вставьте описание и ссылку на сайт (`https://ЛОГИН.github.io/autoflow/`), добавьте темы: `nodejs`, `sqlite`, `telegram-bot`, `vanilla-js`, `portfolio`.
- Закрепите репозиторий в профиле (Customize your pins).
- Зелёная галочка CI рядом с последним коммитом, скриншоты и честный раздел «Что не сделано» в README хорошо читаются рекрутерами.

### Если что-то не работает

| Что видите | Что делать |
|---|---|
| 404 на адресе сайта | Проверьте в Settings → Pages: ветка `main`, папка `/docs`. Подождите пару минут после включения. |
| Страница без стилей или пустая | Откройте именно адрес из Settings → Pages, а не файл из репозитория. Обновите страницу с Ctrl+F5. |
| Видна старая версия | Ctrl+F5. GitHub Pages иногда обновляется с задержкой до 10 минут. |
| «Демо-почта» пуста | Письма появляются после действий: регистрация, «Забыли пароль?», повторная отправка подтверждения. |
| Аккаунт пропал | Демо хранит данные в браузере. Очистка данных сайта, приватный режим или другой браузер начинают всё с нуля, это нормально. |
| Красный крестик в Actions | Выполните `npm run build:demo`, закоммитьте папку `docs` и отправьте. Или откройте лог шага «Автотесты», если упал тест. |

Свой домен: Settings → Pages → **Custom domain** (+ запись CNAME у регистратора домена) → включить **Enforce HTTPS**.

## Часть 2. Настоящий сервер (когда понадобится)

> Эту часть я описал по стандартной схеме, но на реальном сервере её не проверял. Для рассылки по компаниям она не нужна.

Нужен сервер, где можно запускать Node.js 22.5+ (VPS или облачный хостинг) и **постоянный диск** для файла базы. На бесплатных тарифах многих облаков диск стирается при каждом обновлении: данные пользователей пропадут.

### Настройки `.env` для боевого сервера

```
NODE_ENV=production
APP_URL=https://ваш-домен            # обязателен: без него сервер не запустится
HOST=127.0.0.1
PORT=3000
TRUST_PROXY=true                     # если перед Node стоит Caddy или Nginx

MAIL_TRANSPORT=resend                # или smtp (см. guide/CONFIG.md)
MAIL_FROM=AutoFlow <no-reply@ваш-домен>
RESEND_API_KEY=...

TELEGRAM_BOT_TOKEN=...               # необязательно
PAYMENTS_MODE=off                    # пока нет настоящей оплаты (так и по умолчанию в production)
```

**Не включайте `PAYMENTS_MODE=demo` для настоящих клиентов:** в этом режиме любой получает платный тариф бесплатно.

### HTTPS

Проще всего поставить [Caddy](https://caddyserver.com): он сам получает сертификаты. Файл `Caddyfile`:

```
ваш-домен {
    reverse_proxy 127.0.0.1:3000
}
```

### Запуск как служба (systemd)

Файл `/etc/systemd/system/autoflow.service`:

```ini
[Unit]
Description=AutoFlow
After=network.target

[Service]
WorkingDirectory=/opt/autoflow
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning server.js
Restart=always
User=autoflow

[Install]
WantedBy=multi-user.target
```

Дальше: `sudo systemctl enable --now autoflow`, логи: `journalctl -u autoflow -f`. Запускайте **один экземпляр** (иначе бот Telegram будет конфликтовать сам с собой).

### Резервные копии (обязательно)

Вся база это один файл `data/autoflow.db`. Копировать его «на ходу» обычным `cp` нельзя (база работает в режиме WAL), используйте встроенную команду SQLite и храните копии **вне сервера**:

```bash
sqlite3 /opt/autoflow/data/autoflow.db ".backup '/backups/autoflow-$(date +%F).db'"
```

Запускайте её раз в сутки через `cron`. Периодически проверяйте, что копию можно открыть.

### Обновление

```bash
git pull && sudo systemctl restart autoflow
```

Структура базы обновится сама при запуске.

### Перед приёмом денег и данных настоящих людей

Нужны: заполненные «Условия использования» и «Политика конфиденциальности» (сейчас шаблоны, покажите юристу), статус ИП/ТОО, платёжная система вместо заглушки (см. раздел «Тарифы и оплата» в [CONFIG.md](CONFIG.md)), проверка требований законодательства вашей страны к персональным данным.
