# AutoFlow: настройка и возможности (подробная справка)

Краткое описание проекта: [README](../README.md). Выкладка на GitHub Pages и на сервер: [DEPLOY](DEPLOY.md).

## Запуск локально

Нужен **Node.js 22.5 или новее** (проверка: `node -v`). Устанавливать пакеты не нужно — зависимостей нет.

```bash
cp .env.example .env     # по желанию, значения по умолчанию подходят
npm start
```

Откройте http://127.0.0.1:3000. База создаётся автоматически в `data/autoflow.db`.

Тесты: `npm test` (96 тестов)

## Что уже работает (этапы 1–6)

- Регистрация и вход, пароли хешируются через scrypt, сессии в БД (в cookie только случайный токен)
- Страницы `/dashboard`, `/login`, `/register` защищены на сервере
- **Подтверждение email:** после регистрации уходит письмо со ссылкой (действует 24 ч). Токен лежит во фрагменте ссылки (`#token=…`), поэтому не попадает в логи сервера и прокси и в заголовок Referer. В кабинете до подтверждения виден баннер с кнопкой «Отправить ещё раз»
- **Сброс пароля:** «Забыли пароль?» → письмо со ссылкой (30 мин, одноразовая) → новый пароль. После сброса все старые сессии завершаются. Ответ сервера не раскрывает, есть ли такой email
- **Смена пароля** в «Настройках» (по текущему паролю), остальные устройства выходят из аккаунта
- **Форма «Контакты»** на главной: сообщения сохраняются в БД (таблица `contact_messages`) и, если задан `CONTACT_TO`, пересылаются на почту. Есть скрытая ловушка для ботов и лимит запросов
- **Данные кабинета на сервере:** задачи, автоматизации, уведомления, журнал и настройки хранятся в базе и привязаны к аккаунту. После выхода в браузере ничего не остаётся, на другом устройстве видны те же данные. Новый аккаунт получает набор образцов (кнопка «Сбросить» в настройках возвращает их)
- **Автоматизации работают на сервере:** правило срабатывает на событие («Новая задача создана», «Задача выполнена»), либо запускается вручную. Действия не порождают новых событий, поэтому зациклиться правила не могут
- **Telegram-бот:** привязка аккаунта по одноразовой ссылке с подтверждением, команды `/tasks`, `/add`, `/stop`, кнопка ✅ под задачами и уведомления от автоматизаций (см. раздел «Telegram-бот»)
- **Тарифы и заглушка оплаты:** три тарифа с ограничениями, которые проверяет сервер (активные автоматизации: 3 / 25 / 100, Telegram-уведомления от автоматизаций только на «Про» и «Бизнес»). Раздел «Тариф» в кабинете, страница оплаты `/checkout`, история платежей (см. раздел «Тарифы и оплата»)
- Страницы «Тарифы», «Контакты», подвал, «Условия» и «Политика» (шаблоны, см. ниже)
- `/api/session` отвечает гостю `{user: null}` без ошибки, по нему главная узнаёт, показывать ли «Личный кабинет»
- **Защита данных:** владелец записи берётся только из сессии, а любой запрос по номеру записи проверяется на принадлежность (чужая запись выглядит как несуществующая, 404). Подмена владельца в теле запроса игнорируется, значения проверяются по белым спискам и длинам, есть пределы на количество записей и частоту изменений
- Защита: CSRF (Origin + токен), лимиты запросов (в т.ч. на письма) и блокировка подбора пароля, строгая CSP, токены из писем хранятся в БД только в виде хеша, ссылки в письмах строятся из `APP_URL`, а не из заголовка Host

## Telegram-бот

### 1. Создайте бота и получите токен

1. В Telegram найдите **@BotFather** (с синей галочкой) и отправьте `/newbot`.
2. Введите название (любое, например `AutoFlow`) и имя пользователя: оно должно заканчиваться на `bot`, например `my_autoflow_bot`.
3. BotFather пришлёт **токен**: длинная строка вида `числа:буквы_и_цифры` (например, `123456789:AAH...`).

### 2. Добавьте токен в файл `.env`

1. В папке проекта скопируйте `.env.example` в `.env`, если его ещё нет (`cp .env.example .env`, в Windows: `copy .env.example .env`).
2. Откройте `.env` в любом текстовом редакторе и найдите строку `TELEGRAM_BOT_TOKEN=`.
3. Вставьте токен сразу после знака `=`, без пробелов и кавычек:

```
TELEGRAM_BOT_TOKEN=вставьте_сюда_токен_от_BotFather
```

4. Сохраните файл и перезапустите сервер (`Ctrl+C`, затем `npm start`). В консоли должна появиться строка `[telegram] бот @имя_бота готов к работе`.
5. Откройте кабинет → «Настройки» → «Telegram-бот» → «Подключить».

**Токен секретный.** Он даёт полный контроль над ботом. Файл `.env` внесён в `.gitignore`, не отправляйте его в чаты, не публикуйте и не вставляйте токен в код. Если токен попал не туда, в @BotFather выполните `/revoke`, получите новый и замените его в `.env`. На хостинге токен задаётся в переменных окружения, а не в файле в репозитории.

### 3. Как это работает

- **Привязка.** Кабинет выдаёт ссылку `t.me/ваш_бот?start=КОД`. Код одноразовый, живёт 10 минут и хранится в базе только в виде хеша. Бот спрашивает «Подключить чат к аккаунту А***@mail.kz?» и привязывает чат только после нажатия «Да»: без этого чужая ссылка могла бы привязать ваш чат к чужому аккаунту. Один чат можно привязать только к одному аккаунту.
- **Команды в боте:** `/tasks` (активные задачи, под каждой кнопка ✅), `/add текст` (новая задача, правила автоматизаций срабатывают), `/stop` (отключить чат), `/help`.
- **Уведомления.** Автоматизации с действием «Отправить уведомление в Telegram» отправляют сообщение в привязанный чат. Сообщения идут через очередь с повторами; если пользователь заблокировал бота, чат отвязывается сам. Есть лимит: не больше 30 уведомлений за 10 минут на аккаунт. Кнопка «Отправить тест» в настройках проверяет доставку. Переключатель «Telegram» в настройках уведомлений отключает отправку.
- **Безопасность.** Бот работает только в личных чатах, игнорирует группы и других ботов, не отвечает непривязанным чатам ничем, кроме подсказки, проверяет принадлежность задачи аккаунту при каждом нажатии кнопки, отправляет сообщения обычным текстом и ограничивает частоту сообщений от одного чата. Токен не выводится в логи и сообщения об ошибках.

### 4. Важно знать

- Бот работает через *long polling*: серверу не нужен публичный адрес или HTTPS для бота. Запускайте **только один экземпляр сервера** с этим токеном, иначе Telegram вернёт ошибку 409.
- Без токена сайт работает как обычно, а в кабинете вместо кнопки подключения показывается пояснение.
- Для нагруженного продукта позже можно перейти с polling на webhook.

## Тарифы и оплата

Тарифы описаны в одном месте, `src/plans.js` (цены, лимиты). Клиент присылает только код тарифа, цену и срок определяет сервер.

**Режимы (`PAYMENTS_MODE` в `.env`):**

| Режим | Что происходит |
|---|---|
| `off` | Оплата выключена, платный тариф получить нельзя. **Это значение по умолчанию в production.** |
| `demo` | Демо-оплата: страница `/checkout` показывает заказ, кнопка «Оплатить (демо)» активирует тариф на 30 дней. Деньги не списываются, карта не нужна. Значение по умолчанию при разработке. |

**Внимание:** в режиме `demo` любой пользователь получает платный тариф бесплатно. Для портфолио-версии это нормально, для настоящих клиентов нет, там должен стоять `off` (или реальная оплата).

**Как работает:** выбор тарифа создаёт заказ (сумма фиксируется на сервере) → оплата → тариф действует 30 дней, автопродления нет. После окончания срока аккаунт возвращается на «Старт», автоматизации сверх лимита приостанавливаются (самые новые), данные не удаляются. Заказ виден только владельцу, повторная оплата того же заказа ничего не продлевает.

**Подключение настоящей платёжной системы** (позже, после регистрации ИП/ТОО и выбора провайдера): `checkout()` в `src/billing.js` вместо внутренней страницы возвращает ссылку оплаты провайдера, а новый маршрут webhook после проверки подписи вызывает `applyPayment(orderId, providerRef)`. Эта функция уже атомарная и идемпотентная: повторная доставка того же подтверждения тариф дважды не продлит. Также понадобятся чеки (фискализация) и возвраты, они зависят от провайдера и страны.

## Письма

По умолчанию (`MAIL_TRANSPORT=console`) письма **не отправляются, а печатаются в консоль сервера**, там же ссылка для подтверждения или сброса. Для реальной отправки выберите один из двух вариантов и задайте в `.env`:

**Вариант А. Resend (проще всего, нужен API-ключ и свой домен)**

```
APP_URL=https://ваш-домен
MAIL_TRANSPORT=resend
MAIL_FROM=AutoFlow <no-reply@ваш-домен>
RESEND_API_KEY=re_...
```
Домен нужно подтвердить в личном кабинете resend.com (добавить DNS-записи).

**Вариант Б. Любая почта по SMTP (Gmail, Яндекс, Mail.ru, почта вашего домена)**

```
APP_URL=https://ваш-домен
MAIL_TRANSPORT=smtp
MAIL_FROM=AutoFlow <no-reply@ваш-домен>
SMTP_HOST=smtp.yandex.ru   # или smtp.gmail.com, smtp.mail.ru ...
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=...
SMTP_PASS=...              # для Gmail/Яндекса нужен «пароль приложения», а не основной пароль
```
Поддерживается защищённое соединение на порту 465 (порт 587 / STARTTLS не поддерживается). Пароль не отправляется по незащищённому каналу.

`APP_URL` в production обязателен: без него сервер не запустится, иначе ссылки в письмах вели бы на localhost. Чтобы письма не попадали в «Спам», у домена отправителя настраивают SPF и DKIM (инструкции у почтового провайдера).

## Что дальше

- Реальные триггеры автоматизаций: планировщик («Каждый день в 09:00») и входящая почта пока только выбираются, но не срабатывают.
- Реальная оплата вместо заглушки (после регистрации ИП/ТОО и выбора платёжной системы, см. раздел «Тарифы и оплата»).
- Действие «Отправить email» в автоматизациях пока создаёт только уведомление в кабинете, письма не уходят.
- «Командный доступ» в тарифе «Бизнес» помечен как «скоро»: функции пока нет.
- Админка: просмотр сообщений из формы «Контакты», пользователей и заказов.

**Обновление с прошлой версии:** база обновится сама при запуске (миграции выполняются по порядку). Аккаунты, созданные раньше, получат образцы данных при первом открытии кабинета и будут на тарифе «Старт».
